# Awake in Hell

A third-person survival horror / stealth game. **You never fight.** There is no
weapon, no counter, no last stand — the entire verb set is walk, sneak, run and
hide. Being seen is not a fail state, it is the start of the worst part.

Built solo in Unreal Engine 5.7. **In development** — this repository is a
showcase, not the source. Devlog at the bottom.

---

## Engineering highlights

### A hand-written state machine instead of a Behaviour Tree

The pursuer runs `Patrol → Investigate → Chase → Search → Patrol` as a plain
C++ enum with the transitions in a single function.

That is a deliberate choice against the engine defaults. Both StateTree and
Behaviour Trees need editor-authored assets — a BT drags a Blackboard along with
it, StateTree needs a schema — and this project has no editor-authored assets at
all, on purpose. For five states an enum also wins on the things that matter
day to day: transitions are greppable, the current state prints into the debug
overlay as one string, and nothing breaks when the level is regenerated from
scratch. The migration point is written down: past roughly fifteen states, or as
soon as a designer needs to author behaviour, StateTree takes over. The
transitions are already explicit, so that port is mechanical.

What the AI actually does, as opposed to what the state names suggest:

- **Only running makes noise.** Walking and crouching are free. That single rule
  is what turns Shift from a movement default into a decision.
- **Timings cannot be learned.** The same patrol route is almost never walked
  twice in a row, room visits are shuffled within a route, and pauses at
  waypoints vary between one and four seconds.
- **It remembers where it noticed you.** Routes passing near the last known
  position get four times the weight when the next route is chosen, so the
  building quietly closes in around where you were last careless.
- **Search uses NavMesh distance, not straight-line distance.** A room on the
  other side of a wall is correctly treated as far away. Fresh noise during a
  search extends it rather than restarting it.
- **Hiding is a gamble, not an escape.** Hidden, you are invisible to sight, but
  hearing still works, so climbing in can give you away. A pursuer that *watched*
  you climb in walks over and opens it — merely hearing the lid is not enough to
  know which one. During a search, each nearby hiding place is checked on a 0.4
  roll. It might open the door. It might walk past.

### The level is a text file

The playable level is not authored in the editor. It is generated by a Python
commandlet from a plain-text layout: structural bay widths in millimetres, a
room map at one character per bay, and separate sections for doors, patrol
routes and hiding places.

The floor plan itself comes from a **real Soviet-era architectural blueprint
from 1985** — a scanned catalogue sheet, reconstructed at true scale. Millimetres
convert to engine units at a fixed ratio, so the building measures what the
drawing says it measures.

```
COLS 2400 3300 3300 3300 2400 1800 2400 ...
ROWS 3600 5050 2100 2400 2400 2100 5050 5050

MAP
58884.www.zzz.ggg.48885
99999999999999999999999
.....0iiimmlleekk0.....
```

Editing the plan is editing that file. The generator is idempotent — it wipes
everything it previously spawned and rebuilds — so reshaping a wing is a diff,
not an afternoon of dragging boxes. Patrol routes, doorways and hiding places
are spawned by the same pass, which means a level rebuild cannot silently lose
them.

Being honest about the reconstruction: the outer module is measured off the
drawing, but part of the internal dimension chain is illegible on a
forty-year-old scan and was reconstructed from the room schedule areas instead.
Where that happened is marked in the data file rather than quietly smoothed over.

### Lessons learned: navigation

Most of the time lost on this project went into navigation, and none of it was
where I first looked.

**A pursuer that stands still is not always a broken state machine.** The move
request was being re-issued every tick, which aborts and re-paths the move sixty
times a second. Worse, a failed path was being treated as "arrived", so the AI
silently ticked through its entire patrol route without moving a step. Making
failure loud is what produced the diagnosis; until then the logs were clean and
the bug looked like AI logic.

**Doorway width is a navigation parameter, not an art decision.** Real doors in
the drawing are 900 mm. The navigation agent erodes the walkable surface by its
radius from every wall, and at radius 35 that leaves 20 units of walkable strip
inside a 900 mm opening — a strip that appears and disappears between rebuilds.
The symptom was maddeningly specific: the pursuer patrolled corridors perfectly
and would not follow you through a door. Openings went to 1200.

**A headless-generated level has no baked navigation.** Nothing produces a static
NavMesh, so it has to be built at runtime. And the trap underneath that: deleting
the NavMesh actor to have it recreated from project defaults does not work —
nothing recreates it, and navigation vanishes entirely. I did exactly that and
turned zero path failures into 329.

**Verify the fix, not the hypothesis.** Two of my three navigation "fixes"
addressed causes that were not real. The one that mattered came from measuring
the actual values at runtime instead of reasoning about what they should be.

## Stack and principles

| | |
|---|---|
| Engine | Unreal Engine 5.7 |
| Language | C++ only |
| Blueprints | none — no Blueprint is permitted to hold logic |
| Editor-authored assets | none — input mappings are built in C++ at runtime |
| Level authoring | data-driven, generated from a text layout |
| Scope | single machine, single developer, no server |

The no-assets rule is not purism for its own sake. Everything that defines
behaviour lives in text, which means it diffs, reviews and merges. Input
mapping contexts are constructed in code at startup rather than saved as assets,
for the same reason.

## Devlog

### 2026-08-08 — pursuer, hiding, and a building that fights back

Where it stands: a full floor of the building is generated from the layout file
and playable. The pursuer patrols six routes, investigates noise, chases on
sight and searches around your last known position when it loses you. Hiding
places work, with the observed-while-hiding rule and the probabilistic search
check described above. Getting caught resets you to the start.

Deliberately not there yet: no animation — the player and the pursuer are
capsules of different colours; no materials, the level is grey; no sound. The
lighting is currently flat and bright because it is tuned for reading AI
behaviour, not for atmosphere.

Next: cutting the service wing into its real small rooms, which is the layout
the hiding mechanic actually wants, then sound, then the lighting pass this
genre lives or dies on.
